# Upstream sync to v3.1.0 (2026-11)

The third merge of `upstream/main` into the fork (2.8.2 to 3.1.0, through #207), plus the Apple Music blank-tab fix (PR #144) whose upstream merge this sync brought in. Moved out of `docs/plan.md` on 2026-11-06.

- Third upstream sync, v2.8.2 to v3.1.0, as App Store v2.0 (started
  2026-11-06, branch `sync-upstream-3.1` off `main`). Merges the 84
  `upstream/main` commits after `567497b` (#149), up to `86471ac` (#207).
  **Status: done. The user tested it in Safari and said everything looks
  good (2026-11-06). Committed as merge `1ab2ac4` plus the
  collection-settings fix `de1825b`, `main` fast-forwarded and pushed, and
  the branch archived as `refs/archive/sync-upstream-3.1`. The Xcode repo's
  version bump (v2.0, build 13, macOS 12.0) is pushed too.** The macOS app builds
  with the deployment target at 12.0, see below. `tsc` is clean and vitest passes
  (127 files, 1643 tests). ESLint on `src` shows only three errors, all in
  files identical to upstream (`hide-ratings/app.test.ts`,
  `timeline/graph.ts`, `metalarchives/resolve.ts`), left alone. `npm run
  build:safari` succeeds, and `dist/`'s top-level entries still match the
  Xcode project's `../../dist/...` references, so no new bundle resources
  are needed. The user's collection-settings fix came along in the
  working tree and was committed separately as `de1825b`.

  How it was resolved:
  - Most conflicts were add/add in `release-submission/`: the user's PR
    #150 arrived on both sides (upstream merge `e9a0f83`), and kknq then
    reworked it heavily (`9d7f253`, `a82513a`, `e26d990`, the credit
    suggestions from each service, the alias fixes, the case buttons). The
    PR branch had merged upstream through `3270ee6`, so `e9a0f83^2` is a
    safe merge base for the 32 files upstream didn't touch between
    `567497b` and `e9a0f83^1`. Re-merging against it showed the fork's only
    changes there were file headers and synchronous rewrites for the fork's
    `runScript`. So every one of those files is now upstream's version with
    the fork's header block on top, not a mix.
  - `runScript` (`shared/utils/dom.ts`) still injects a `<script>`
    synchronously, but now returns `Promise.resolve()`. Upstream's callers
    `await` it, and `await-thenable` would fail on `void`. The fork's bare
    calls in `chart-shortcuts/app.ts` gained `void`. Upstream's `runScript`
    never returns a value, so nothing reads one.
  - Fork-only behavior kept on top of upstream: the album-header VA check
    (`getAlbumHeaderArtists`, rebuilt on kknq's JSON walker in
    `applemusic/track-artists.ts`, sharing `parseLockupScript`, with tests
    in `resolve.test.ts`); the mobile stream-links placement in
    `stream-links/app.tsx` (upstream's new `placement.ts` and its test are
    now unused on the fork); `vite.config.ts`'s display name and debug page,
    which is listed outside upstream's MV3-only offscreen ternary so
    `build:safari:debug` keeps it; the import checkmark waiting for the fill
    (`import-controls.tsx` calls `setInfo` in a `finally`, because the
    fork's `useReleaseInfo` never sets "complete" itself); the emoticon
    uppercase rule in `capitalization.ts`, while the fork's
    `RELEASE_FORMATS` gave way to upstream's `UPPERCASE_EXCEPTIONS` (EP, LP,
    NTS); `buildLinkedTitle` staying in `artist-shortcuts.ts`, imported by
    `track-artist-links.ts`; the iOS direct-fetch path in
    `shared/utils/fetch.ts`, which now skips `null`/`undefined` URL
    parameters.
  - Taken from upstream: Apple Music search (the fork's copy was identical
    to `71e70da`, PR #144), `use-page-data.ts` (#144 plus kknq's
    lowercasing and `music-video` path, which completes the #144 entry
    above), both Qobuz files (kknq moved to an `open.qobuz.com` API loader
    that forces `us-en`), Tidal search (both sides had made the same fix),
    `background/fetch.ts` (upstream adopted the fork's error-body union),
    `types.ts`, `hide-ratings/generic-page.ts`, `fillers.ts` and
    `page-functions.ts` (kknq split `fill` out into `fill.ts` and
    `field-fillers.ts`, which keeps the "always reset the artist picker"
    rule). `messaging.ts` is a union, still without upstream's
    `keybindingsChanged`. `package-lock.json` is upstream's, regenerated by
    `npm install`; it differs only by the fork's `selenium-webdriver`.
  - Fork-side test fixes: `popup/shortcut-view.test.tsx` uses the actions'
    `defaultBindings` directly (the fork keeps `ctrl+` defaults, so it has
    no `resolveDefaultBindings`), and `hide-ratings`/`hide-reviews`
    `app.test.ts` also mock `~/shared/utils/messaging`, since the fork reads
    toggles through the background script rather than `storage`.
  - Versions: `package.json` is 3.1.0. The Xcode project is set to
    `MARKETING_VERSION` 2.0 (first 1.4) and `CURRENT_PROJECT_VERSION` 13 in the same
    four places as the 1.3 bump (`4473f69`).

  Resolved 2026-11-06: the user chose 12.0, set in all four macOS build settings, and the macOS `xcodebuild` now succeeds. Before that, `xcodebuild` failed with "The macOS deployment target … is set to
  11.0, but the range of supported deployment target versions is 12.0 to
  27.2.x", on both macOS targets. So 11.0, which v1.3 shipped with, can't be
  built with the installed Xcode. The user wants to support as many users
  as possible.

  Open questions left after the sync, tracked in `docs/todo.md`:
  - Upstream's new `reference-links/settings.ts` and `user-page/settings.ts`
    write to `storage.local` directly, so Safari's "clear history" would
    wipe them. Moving them onto `stored-settings` would be a fork change to
    upstream files.
  - Upstream's Spotify diagnostics content script
    (`spotify-search/page-errors.ts`) uses `world: "MAIN"`, which is now in
    the MV2 Safari manifest. Whether Safari honours it is unchecked.
  - kknq's tracklist picker now appears on non-VA releases too (`9d7f253`),
    with an opt-in "Add to track titles" button for release artists. The
    user decided to keep kknq's behavior as is (2026-11-06).

  `187349a`): kknq/even-better-rym#144, open. Upstream had since added a
  second lookup step to the Apple Music search, so the port kept their code and
  applied only the rename and host change.
